# Intake Issue

Clarify the issue into a concise, actionable task. Component-scoped work goes
in this repo's `tasks/`; cross-cutting deployment, infrastructure, or HACS
pipeline work goes in `~/dev/infra/tasks/`. Preserve the issue's intent and
include context, scope, acceptance criteria, validation, and security
considerations. Use the repo's task-numbering convention and regenerate
`TODO.md` when metadata changes. Do not create or update a remote issue unless
the user explicitly asked for that action.
